# Demonstration script — under five minutes

Record the real application. Show the actual runtime card; never edit a local red
status into a COOL-verified green one. If AWS work remains incomplete, say so plainly.

| Time | Screen/action | Narration cue |
|---|---|---|
| 0:00–0:20 | Team introduction, app title | “COOLForge makes OpenCV faster without breaking what it sees.” |
| 0:20–1:00 | Inspect scratch, crack, and pit examples | Explain original pixels, exact ground truth, predicted mask, boxes, and foreground F1. |
| 1:00–1:30 | Configuration and stage timings | Explain why scaling or morphology can affect both runtime and defects. |
| 1:30–2:30 | Run Autotune with 12 iterations | Show genuine progress, a rejected candidate, the recorded reason, and a later decision. |
| 2:30–3:05 | Proposal vs incumbent and held-out scores | Explain rollback, bounded search, and synthetic-data limits. Show approval/export and live preview. |
| 3:05–3:45 | Architecture + environment evidence | Show the core loop and intended/actual Graviton deployment. Distinguish what ran from what remains. |
| 3:45–4:20 | Benchmarks tab | Load real stock/COOL artifacts if available; otherwise show the explicit missing-evidence state. Never substitute fixtures. |
| 4:20–4:45 | Tests, report, limitations | Mention thin-crack loss, timing noise, representative data, and required human review. |
| 4:45–4:55 | Repository and closing | Point judges to reproducible commands, source, and measured evidence. |

For the team segment, use the actual participant names and recorded introduction.
Do not invent team footage, an endpoint, or a video URL. Rehearse once and keep enough
time for the trace to finish. A separate local screen recording is acceptable only if
clearly labeled; final AWS requirements still need truthful evidence.
